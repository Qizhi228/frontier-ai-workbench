# 面试讲解提纲

## 30 秒介绍

我做了一个单用户的前沿 AI 技术研究工作台。用户输入研究主题后，系统通过来源适配器收集资料，去重后生成带引用的技术简报，并把任务、报告和来源保存到 SQLite 与 Markdown。第一版默认 Mock，接入真实模型和网页来源时只替换适配器，不改变核心工作流。

## 为什么不做完全自主 Agent

第一版选择固定工作流，是因为研究任务的步骤可以明确表达，也更容易测试、调试和解释。自由 Agent 可以作为后续升级，但工具仍然必须通过权限策略，不能因为模型输出了一个动作就直接执行。

## 为什么保存 Markdown 和 SQLite

SQLite 保存任务状态和来源元数据，Markdown 保存人可读的报告。单用户场景不需要一开始引入 PostgreSQL、Redis 和复杂对象存储；同时 Markdown 可以直接进入个人知识库和作品集。

## 真实来源如何接入

`WebPageSourceProvider` 是来源适配器。它负责抓取页面、提取标题和摘要，`SourceCatalog` 负责把多个来源统一并去重。生产环境还应增加 RSS、GitHub Release、arXiv API、重试、缓存、限流和 robots/版权边界。

## 如何减少错误

- 报告必须列出来源 URL 和发布时间
- 模型只接收来源摘要，不允许凭空补事实
- 无来源时使用 Mock 兜底，但明确标记限制
- 重要结论需要人工核验
- 高风险工具动作默认审批
